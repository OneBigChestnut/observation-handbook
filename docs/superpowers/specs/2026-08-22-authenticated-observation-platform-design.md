# 已登录观察手册平台设计

## 目标

将当前单页、内存状态的界面原型迁移为可本地运行的真实单体系统。系统以独立账号和密码登录为入口，在家庭、小朋友、模板、导出与公共空间之间落实服务端权限和数据隔离；保留现有正式、现代、档案出版物风格的界面基线。

## 范围与约束

- 全站只支持 A5 竖版；不出现 A4、横向模板或纸张大小选择。
- 不依赖旧项目的代码、包、运行数据或业务数据；空数据库可独立初始化。
- 家庭有且仅有一名家庭管理员，可有多名只读成人。
- 卡片、标签、手册和导出文件均只属于一个小朋友，并通过小朋友归入一个家庭。
- 所有公共空间内容均要求登录后才能阅读；不同家庭的登录用户可以阅读已经发布的手册。
- 家庭不可自定义模板；不提供自由页面编辑。
- 模板、导出、成员和发布的关键变更应写入审计日志。

## 运行架构

保留 Vite + React 作为前端，增加同仓库的 Fastify API 服务。API 使用 Prisma 访问 SQLite；照片原图和缩略图保存在本地受控媒体目录，数据库只保存文件元数据和路径。以后迁移到 PostgreSQL 时仅替换数据库配置与迁移流程，不改变业务接口。

浏览器不再保存权威业务数据，也不自行决定权限。每个写入请求由服务端根据会话、家庭成员关系和资源归属复核。前端只通过 API 获得当前账户有权访问的数据。

```text
React / Vite
  └─ HTTPS/HTTP API + 会话 Cookie
       └─ Fastify
           ├─ 权限与资源范围校验
           ├─ Prisma + SQLite
           ├─ 本地原图 / 缩略图媒体目录
           └─ PDF 生成与导出快照目录
```

## 身份、家庭与权限

### 数据实体

- `Account`：账号名、密码哈希、状态、平台角色。
- `Session`：登录会话、失效时间、账户 ID。
- `Family`：家庭空间。
- `FamilyMembership`：账户与家庭关系，角色只能为 `admin` 或 `reader`。每个家庭恰有一个 `admin`。
- `Child`：属于一个家庭的小朋友。
- `AuditLog`：操作者、家庭范围（如适用）、动作、目标类型、目标 ID、时间和结构化元数据。

密码以不可逆哈希保存。密码重置在第一阶段生成由管理员使用的新临时密码并强制用户下次登录后修改；不接入邮件发送服务。

### 访问矩阵

| 身份 | 自己家庭内容 | 公共空间 | 家庭成员 | 发布/撤回 | 后台中心 |
|---|---|---|---|---|---|
| 未登录 | 不可访问 | 不可访问 | 不可访问 | 不可访问 | 不可访问 |
| 家庭管理员 | 读写 | 只读 | 管理本家庭 | 可操作本家庭手册 | 不可访问 |
| 只读成人 | 只读 | 只读 | 只读 | 不可操作 | 不可访问 |
| 超级管理员 | 仅通过明确后台账户管理入口读取元数据，不编辑观察内容 | 只读 | 管理平台账号与家庭账户 | 不代替家庭管理员发布 | 可访问 |

运营管理员可以处理后台被明确授权的日常账号事务，但不取得超级管理员入口，也不取得家庭内容编辑权。

## 内容模型与儿童隔离

- `ObservationCard`：`childId`、记录日期、文字、卡片模板版本 ID、创建/更新时间。
- `CardPhoto`：卡片照片顺序、原图媒体 ID、缩略图媒体 ID、尺寸元数据。
- `Tag`：`childId`、名称、颜色；同一儿童内名称唯一。
- `CardTag`：卡片与标签多对多关联。
- `Handbook`：`childId`、名称、内容介绍、开始/完成时间、封面照片、封面/封底模板版本、家庭/公开可见性。
- `HandbookCard`：手册与卡片多对多关联，允许一张卡片收录于多个手册。
- `HandbookTag`：手册与标签多对多关联。
- `GeneratedExport`：`childId`、手册 ID、屏幕/印刷类型、文件路径、生成时间、内容快照和模板版本快照。

从标签创建手册时，系统预填该标签已有的同儿童卡片与标签关联。后续新增同标签卡片时，前端展示可加入的关联手册选项，由用户明确选择；不会自动把卡片加入所有同标签手册。手册详情展示关联标签，标签详情展示同儿童卡片和关联手册数。

所有资源查询都通过当前会话的家庭范围和资源的 `childId` 共同校验；仅在 UI 中隐藏内容不构成权限控制。

## 模板与版式

模板由超级管理员统一管理，分类固定为：封面、封底、1 张照片卡片、2 张照片卡片、3 张照片卡片、4 张照片卡片。每种模板均为 A5 竖版。

`TemplateVersion` 保存分类、版面定义、预览图、状态、创建信息和使用次数。未使用版本可编辑、删除；任一手册、卡片或导出引用后，该版本的版面定义和名称均锁定，只能改为停用。停用版本不再显示于新建内容选择器，但所有旧内容继续按引用版本显示。

创建卡片时只能选择其照片数对应的已发布卡片模板。创建手册时选择已发布封面和封底模板。所有业务引用保存模板版本 ID，导出时保存独立模板快照，而不是显示名称。

## 媒体与 PDF 导出

上传照片后服务端保存原图并生成多个固定尺寸的缩略图。卡片列表、月历、时间流、标签详情和手册预览只返回缩略图 URL；PDF 生成服务读取原图或适合印刷分辨率的派生图。

导出由家庭管理员在“导出手册”对话框选择手册和类型后创建。已生成文件可下载或删除；删除只移除该导出文件及其记录，不改变手册、卡片和模板。

- 屏幕 PDF：148 × 210 mm 成品 A5，无出血、无裁切线。
- 印刷 PDF：154 × 216 mm 成品画布，四边各 3 mm 出血；A5 成品线为 148 × 210 mm，裁切线置于成品线外。
- 印刷生成前检查每张图片的有效分辨率、安全区和文字溢出。预检失败时不生成可下载文件，并显示具体问题。
- PDF 生成时冻结手册元数据、卡片顺序与内容、媒体引用、模板版本和版面定义，确保旧导出文件始终可重现其生成时状态。

## 公共空间与后台

公共空间只对已登录账户开放，只查询 `visibility = public` 的手册。公共阅读页可以显示发布家庭、记录小朋友、手册信息、卡片和对应版式；不返回家庭成员、内部标签管理、导出文件、编辑功能或未发布内容。家庭管理员发布后立即可见，撤回后立即不可见。

后台中心只对超级管理员开放，拆分为：平台成员与家庭账号、模板管理、审计日志。后台查看家庭账号时只管理账户与成员元数据，不取得对家庭观察内容的编辑权限。

## 迁移策略

1. 将现有视觉组件从 `main.tsx` 拆分为页面、组件和 API 客户端；保留已确认的紧凑档案式布局。
2. 建立数据库迁移、初始超级管理员和明确标记为开发环境的演示种子数据。
3. 先实现认证、会话、家庭、小朋友以及服务端资源范围校验。
4. 再接入卡片、照片、标签、手册与多对多关联，替换前端内存状态。
5. 接入模板版本锁定、导出快照、公共空间和审计日志。
6. 删除原型中全局共享的示例内容及硬编码角色；不读取或迁移旧项目数据。

## 失败处理与验证

服务端统一返回结构化错误：未登录、无权限、资源不存在、资源范围不匹配、业务规则冲突和导出预检失败。前端将错误显示为紧凑提示，不用乐观状态替代服务端结果。

验证包括：

- 单元测试：1–4 张照片、唯一家庭管理员、儿童资源隔离、模板版本锁定、发布权限、导出快照。
- API 集成测试：未登录拒绝、只读成人拒绝写入、跨家庭及跨儿童资源拒绝。
- 端到端测试：管理员完成“记录 → 标签主题 → 手册 → 发布 → 导出”，只读成人只能阅读。
- PDF 视觉验证：屏幕版 A5、印刷版 3 mm 出血和裁切线、封面、封底及四类卡片版式。
- 首次启动验证：空 SQLite 数据库可以迁移并启动，不依赖旧项目内容。

## 非目标

第一阶段不包含云端部署、第三方登录、邮件真实投递、在线支付、家庭自定义模板、自由页面编辑，也不导入任何旧项目或原型运行数据。
