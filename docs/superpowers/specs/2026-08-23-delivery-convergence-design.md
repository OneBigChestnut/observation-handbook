# 观察手册交付架构收敛设计

## 决策

继续采用单体架构：React/Vite 家庭应用、Fastify API、Drizzle ORM、SQLite、本地受控媒体目录和服务端 PDF 任务。不会拆分微服务，也不会更换 ORM 或重建已经实现的认证基础。

`main` 是唯一可交付分支。它必须始终能够通过类型检查、测试和生产构建，并提供可复现的本地启动流程。浏览器内存原型只能作为视觉参考；不得再作为后续业务功能的实现基础或验收对象。

## 当前基线

当前 `main` 只包含视觉原型和领域纯函数。它没有 API、数据库、登录、会话、受控媒体或服务端授权，因此不能满足产品的登录、儿童隔离、只读角色、公开阅读和出版导出要求。

`codex/authenticated-platform-foundation` 已实现认证、Drizzle/SQLite、家庭与儿童范围校验、受控媒体缩略图、卡片、标签和手册 API，以及部分 Web API 接入。该分支当前有未提交的 `CreateHandbookForm` 与测试；表单调用的 `apiClient.createHandbook` 尚未定义，导致类型检查失败。该缺口是收敛工作的首个目标。

## 目标架构

```text
React/Vite
  ├─ auth/                 登录门禁与当前会话
  ├─ api/client.ts         唯一浏览器 API 边界
  ├─ content/              卡片、标签、手册、导出界面
  ├─ admin/                超级管理员界面
  └─ main.tsx              路由和受控壳层装配
          │ HTTP + httpOnly 会话 Cookie
Fastify
  ├─ routes/               身份、家庭、内容、模板、导出、公开、后台
  ├─ auth.ts               会话解析与 RequestActor
  ├─ db/schema.ts          Drizzle SQLite 模型及迁移
  ├─ media/                原图、缩略图、印刷派生图及授权读取
  └─ exports/              预检、PDF 渲染、不可变快照
```

浏览器只保存暂存表单、当前导航和从 API 读取的显示状态；所有卡片、标签、手册、模板、成员、发布和导出文件以 API 与数据库为权威来源。

## 不可变规则

- 全站只支持 A5 竖版。
- 每个家庭恰有一个 `admin`；其余成人为 `reader`；只有 `super_admin` 能访问后台中心。
- 卡片、标签、手册、导出和媒体必须关联 `childId`，并由当前会话的家庭范围与资源归属共同校验。
- `reader` 只能读取有权访问的内容，不得创建、编辑、发布、导出或管理成员。
- 公共空间只对已登录账户开放；发布和导出均保存不可变快照。
- 未使用模板可以编辑或删除；一旦被引用，模板版面与名称冻结，只能停用。
- 原图、缩略图和印刷派生图均由服务端受控存储和授权读取；不得依赖第三方示例图片作为业务媒体。

## 收敛阶段

### 阶段 0：修复并合并认证内容基础

在 `codex/authenticated-platform-foundation` 完成 `apiClient.createHandbook`，将 `CreateHandbookForm` 接入受控壳层，并移除 `main.tsx` 中对应的内存写入流程。提交目前未跟踪的表单和测试，确保完整测试、类型检查和 Web 生产构建均通过。

合并前验收：从空 SQLite 数据库迁移与种子开始，管理员能登录并为当前儿童创建卡片、标签和手册；只读成人可以读取但所有写入返回 403；跨家庭与跨儿童请求返回 403；刷新页面后数据保留。满足后才可合并至 `main`。

### 阶段 1：完成家庭内容生命周期

实现卡片编辑、归档/软删除、被手册引用时的删除检查、手册卡片排序和完成观察状态。所有变更写审计日志，所有 mutation 由服务端基于 `RequestActor` 决定权限。

### 阶段 2：全局 A5 模板版本

实现超级管理员专属的封面、封底和 1–4 图卡片模板版本管理。模板引用采用 ID 和快照；已引用版本不可编辑或删除。家庭管理员只能选择已发布模板。

### 阶段 3：出版级导出任务

服务端创建导出任务并冻结手册、卡片顺序、媒体、模板和预检结果。屏幕 PDF 为 148×210 mm，无出血和裁切线；印刷 PDF 为 154×216 mm，四边 3 mm 出血并有裁切线。预检失败不得生成可下载文件。

### 阶段 4：已登录公共发布

发布生成面向已登录读者的安全公开快照；手册后续编辑不改变已发布版本。撤回和后台下架必须立即隐藏公开版本。公开投影不得返回成员、导出、原图路径或编辑元数据。

### 阶段 5：成员、家庭与审计后台

实现家庭管理员的成员增删和临时密码重置，以及超级管理员的家庭账号、模板和审计日志界面。后台只能管理账户元数据与平台资源，不能绕过家庭内容权限。

### 阶段 6：发布验收

补齐端到端流程、PDF 视觉验证、桌面/平板/手机导航验证、README 中的安装/迁移/种子/备份恢复说明。仅所有门槛均通过时，项目才视为可发布。

## 计划与文档治理

`2026-08-22-observation-handbook-master-plan.md` 是唯一权威实施计划，后续将按本设计重写。此前的 Prisma 基础计划和标签驱动计划保留为历史参考，不得作为新任务来源；Drizzle 是唯一数据层规范。

每个阶段都必须以失败测试开始，并以 API/前端针对性测试、完整测试、类型检查、Web 构建和 `git diff --check` 结束。一个阶段只有在验收门槛通过且提交已进入 `main` 后才能计入进度。

## 非目标

本轮不引入云端部署、第三方登录、邮件投递、支付、家庭自定义模板、自由页面编辑或旧项目数据迁移。
