# 持久化观察内容设计

## 目标与范围

在已完成的登录、家庭和小朋友范围校验之上，将“今日记录、标签管理、观察手册”从浏览器内存状态迁移到 SQLite（Drizzle ORM）。本阶段处理卡片、其最小媒体资产与缩略图、标签、手册和它们的关联关系；不实现模板版本、PDF、公共空间或后台页面的真实数据迁移。

所有内容仍固定为 A5 竖版，且完全归属于一个小朋友。家庭管理员可写，家庭只读成员仅可读。任何 API 均不得以客户端传入的家庭 ID 作为授权依据。

## 数据模型

新增以下 SQLite 表，并以外键和唯一索引保护基本关系：

| 表 | 关键字段与约束 |
| --- | --- |
| `observation_cards` | `id`、`child_id`、`observed_at`、`text`、`created_at`、`updated_at`；卡片文字可为空，但创建事务必须写入至少一张照片。 |
| `media_assets` | `id`、`child_id`、原图受控路径、缩略图受控路径、MIME 类型、像素宽高、创建时间；文件不由公开静态目录直接暴露。 |
| `card_photos` | `card_id`、`media_asset_id`、`position`；`position` 唯一且范围为 0–3，创建卡片事务必须写入 1–4 条记录。 |
| `tags` | `id`、`child_id`、`name`、`color`、`created_at`；`(child_id, name)` 唯一。 |
| `card_tags` | `card_id`、`tag_id` 复合主键；写入时验证两者归属同一小朋友。 |
| `handbooks` | `id`、`child_id`、`title`、`introduction`、`started_at`、`completed_at`、`visibility`（本阶段固定 `family`）、时间戳；完成时间为空即持续观察。 |
| `handbook_cards` | `handbook_id`、`card_id`、`position`；同一张卡片可出现于同一小朋友的多本手册，但不可跨儿童关联。 |
| `handbook_tags` | `handbook_id`、`tag_id` 复合主键；仅允许同儿童标签。 |

不提前建立 `template_versions` 或导出快照表，避免临时字段假装完成后续子系统。媒体能力仅包含受控本地文件、固定尺寸缩略图与授权读取，不包含相册管理、图片编辑或印刷派生图。数据库迁移只增表，绝不导入原型的示例内容。

## API 与权限

所有路由先从会话取得 `RequestActor`，再经 `childId → child.familyId → membership` 验证。

| 路由 | 读取/写入 | 行为 |
| --- | --- | --- |
| `POST /api/children/:childId/media` | 仅家庭管理员 | 接收 1 张图片，写入受控原图与固定缩略图；读取时再次按儿童范围授权。 |
| `GET /api/children/:childId/cards` | 家庭成员可读 | 默认按观察日期倒序；支持月、时间流、月历均复用同一列表数据。 |
| `POST /api/children/:childId/cards` | 仅家庭管理员 | 新建卡片及标签关联，在一个事务内写入审计日志。 |
| `GET/POST /api/children/:childId/tags` | 成员可读、管理员可写 | 返回当前儿童标签及卡片/手册计数；名称在该儿童范围内唯一。 |
| `GET/POST /api/children/:childId/handbooks` | 成员可读、管理员可写 | 返回手册摘要及关联标签、卡片数量；创建时可接收同儿童的预选标签和卡片。 |
| `GET/PATCH /api/handbooks/:handbookId` | 成员可读、管理员可写 | 编辑名称、介绍、开始/完成时间及显式卡片、标签关联。 |

本阶段不会提供发布或导出路由。读者对写入一律得到 `403 FAMILY_ADMIN_REQUIRED`；跨家庭或跨儿童资源读取、写入均得到 `403`，不存在的资源返回 `404`。

## 标签驱动手册规则

从标签创建手册时，服务端读取该标签下的同儿童卡片，预填为初始关联；前端可以展示并让管理员调整。日后新建带相同标签的卡片不会自动加入所有相关手册，创建卡片请求必须明确带入待关联的 `handbookIds`，并由服务端逐个验证小朋友归属。

标签详情展示：标签本身、同儿童卡片、关联手册数量。手册详情展示：关联标签及按 `position` 排列的卡片。删除与编辑策略本阶段采取保守做法：卡片和标签不提供删除接口；后续在媒体、模板和导出引用关系稳定后，再定义可恢复删除策略。

## 前端迁移边界

在 API 完成并有集成测试后，家庭端依次改造：

1. 今日记录按当前儿童读取真实卡片，并保留“按月 / 时间流 / 月历”切换。
2. 标签页读取真实标签与统计，标签详情只显示当前儿童内容。
3. 观察手册读取真实摘要和详情；新建手册必须包含名称、内容介绍、开始/完成时间。

卡片列表、月历、时间流、标签详情和手册预览只接收授权后的缩略图 URL；原图仅用于后续印刷导出。本阶段即接入 1–4 张图片选择与上传，但不提供自由裁剪、编辑或印刷预检。创建卡片请求只接收已属于当前儿童的 `mediaAssetIds`，服务端在同一事务中验证数量与归属，禁止浏览器 URL 或媒体占位键。

## 失败处理与验证

- 领域单元测试：卡片 1–4 张照片、标签名唯一、标签/卡片/手册跨儿童关联拒绝、完成时间决定手册状态、显式关联不自动扩散。
- API 集成测试：未登录 401、读者写入 403、跨家庭 403、同儿童成功写入与审计日志。
- 前端测试：当前儿童切换后只请求并渲染该儿童的内容；没有已迁移数据时显示紧凑空状态。
- 回归：A5 竖版约束、公共空间登录门禁、家庭单管理员规则保持不变。

## 交付顺序

1. Drizzle schema、迁移、最小媒体存储、领域规则和 API 集成测试。
2. 卡片与标签 API。
3. 手册与多对多关联 API。
4. 家庭端三个页面读取真实数据，删除对应的全局示例状态。

模板版本、媒体缩略图、PDF 快照、公共发布与后台真实管理分别进入后续独立阶段。
